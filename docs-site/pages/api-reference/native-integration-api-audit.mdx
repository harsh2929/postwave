# Native Integration API Audit

This page is the working audit for Moosewave-managed native integrations. It
separates three states that must not be collapsed:

| State                      | Meaning                                                                                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verified_native`          | Moosewave owns auth, sync, webhooks or polling, pagination, rate-limit handling, retries, monitoring, disconnect, and tests for the provider's current official API.                                                             |
| `delegated_native_surface` | Moosewave owns the customer-facing surface, but the connector is delegated to an existing product area such as commerce, warehouse, ads, SMS, or chat. It still needs surface-specific proof before it counts as fully verified. |
| `native_foundation`        | Moosewave has catalog/spec/lifecycle/health metadata, but provider-specific API verification and adapter tests are still in progress.                                                                                            |

Readiness may pass for catalog integrity while the stronger public claim remains
blocked. The public claim is safe only when `marketable_public_claim=true` and
the readiness report shows `native_verification_parity=true`.

Klaviyo now has two intentionally separate surfaces: `klaviyo` is a native
foundation row for managed-provider tracking, while `klaviyo-migration` remains
an API-backed migration-to-live source through `/api/v1/migrations` and
source-event polling. The native row reuses migration/source-event evidence
today; provider-row credentials, OAuth/public app install, native webhooks,
writeback, cleanup automation, and live certification remain open.

## Verification Bar

Each verified native connector needs evidence for:

- Auth and token refresh, including OAuth state/PKCE where required.
- Secret storage through credential references only.
- Provider-specific scopes or permissions.
- Incremental sync and backfill for mapped objects.
- Webhook signature or alternative authenticity proof where the provider offers one.
- Pagination/cursor handling.
- Rate-limit and retry behavior, including `Retry-After` or vendor-specific quota headers.
- Idempotency for duplicate webhooks and replayed sync pages.
- Disconnect/revocation and local data-delete handling.
- Contract tests covering auth, sync, pagination, retries, idempotency, and disconnect.

## Current Guardrail

The integrations contract now exposes:

- `native_managed`: Moosewave owns the connector foundation.
- `native_verified`: the connector is `runtime_status=available`.
- `implementation_depth`: `verified_native`, `delegated_native_surface`, or `native_foundation`.

This prevents a `native` badge with `runtime_status=partial` from being marketed
as fully built out.
